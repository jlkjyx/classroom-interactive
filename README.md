# 课堂实时互动系统

手机扫码参与 · 大屏实时呈现 · 让每一次举手都被看见

零数据库依赖，单容器部署，控制端 / 大屏 / 手机三端实时同步。

---

## 一、三个端

| 端         | 地址               | 用途                         |
| --------- | ---------------- | -------------------------- |
| **教师控制端** | `/c`             | 建课堂、发活动、看数据、管积分。留在你的电脑或平板上 |
| **大屏呈现端** | `/w?room=XXXXXX` | 投到投影仪，按 `F11` 全屏。所有可视化都在这里 |
| **学生手机端** | `/m?room=XXXXXX` | 扫码进入，无需安装 App、无需登录         |

学生端链接会由服务端自动生成二维码，教师端和大屏上都能看到。

## 二、功能清单

### 1. 投票 / 随堂小测

- 最多 8 个选项，支持单选 / 多选
- 大屏实时柱状图，票数变化时数字滚动 + 柱子发光脉冲
- 可预设正确答案，一键「公布答案」：正确项变绿打勾，错误项变灰
- 内置常用模板：是/否、听懂了吗、语速合适吗、A/B/C/D

### 2. 词云 + 弹幕

- 学生提交词语，**相同的词会自动聚合并放大**（螺旋布局 + 碰撞检测，字号按词频映射）
- 弹幕**冲入式飞入**：从右侧加速冲进屏幕，再匀速飘过，多轨道自动调度不重叠
- 三种模式：词云 + 弹幕 / 仅词云 / 仅弹幕
- 频次 ≥2 的词右上角显示计数角标
- **可暂停**：结果继续留在大屏上，只是不再收新内容（与「结束」分开，见下）

### 3. 提问大转盘

- Canvas 绘制多色扇区，5 圈缓动旋转 + 逐格 tick 音效
- 抽中后：金色高亮 + 两侧礼炮 + 彩带爆发 + 中奖卡片
- **候选池三选一**（鼓励前排的关键）：
  - 全部在线同学
  - **仅前排同学** → 坐前排的人被点到的概率变成 100%
  - 仅举手同学
- 自动排除已抽中者，抽完一轮自动重置

### 4. 前排就坐激励

- 学生扫码后在手机上点座位（可视化座位图）
- **选前排自动 +3 分**（分值可改），大屏实时显示「前排就坐率」进度条
- 前排座位常驻金色脉冲光环
- 一键「给前排同学加分」，可按前排率自动切换鼓励语
- **座位可改**：点自己的座位退座重选；点别人的座位会提示是谁占着，不会顶替
  （前排内换座不重复加分）

### 5. 互动题库（课前录题，课堂一键发布）

- 四类题目：📊 投票 / 📝 小测 / 💬 词云 / ⚡ 抢答
- 课前把要问的录进去，上课点「📤 发布」直接开活动，不用现场手打题干选项
- 发布后自动切到对应面板看结果；题库随课堂一起保存，下次课还在

### 6. 暂停 / 结束是两件事

每个活动（投票、词云、抢答）都有独立的暂停键：

| 操作     | 结果                                  |
| ------ | ----------------------------------- |
| ⏸ 暂停  | 停止收答案，但**结果继续挂在大屏上**，可随时「▶ 继续」 |
| ⏹ 结束  | 归档本次活动，结果从大屏撤下                |

以前只有开始和结束，一点结束大屏结果就没了——想让学生看着结果讲两句都做不到。

### 7. 多节课：一学期一个课堂码

`设置 → 课堂管理`：

| 操作        | 清什么                  | 留什么                      |
| --------- | -------------------- | ------------------------ |
| **开始新的一课** | 活动记录、分组、举手、词云、座位、本次得分 | **名单 + 累计总积分**（同学不用重新扫码，会被引导重选座） |
| **清空全部数据** | 连学生和积分一起清（换班/新学期才用） | 课堂码、教师口令、设置、题库           |

> 教室座位每节课可能变（按小组坐 / 换教室），所以新一课要清空座位——同学打开手机会
> 直接进选座页，选完就回到主界面，累计积分一直保留。

### 8. 其他课堂工具

| 工具      | 说明                       |
| ------- | ------------------------ |
| ⚡ 抢答    | 抢答**不自动加分**，老师在控制端按"答对 / 答错 / 0 分"判定（默认答对 +5、答错 -2，可在设置改） |
| 🎡 大转盘 | 抽到人**不自动加分**，老师按"答对 / 答错 / 0 分 / 自定义"判定（默认答对 +3，可在设置改） |
| ⏱ 计时器   | 常驻大屏底栏，不打断其他活动，最后 10 秒变红 |
| ✋ 举手    | 学生一键举手，大屏侧栏实时显示        |
| 👏 喝彩   | 学生送表情，大屏飞入 + 彩带          |
| 👥 随机分组 | 一键分组，结果同步到大屏和每个人的手机      |
| 🏆 积分榜  | 大屏 FLIP 动画实时换排名，分数变化闪黄；显示总积分 + 本次得分两段   |
| 🎉 特效   | 一键在大屏炸出「太棒了」「答对了」等特效字    |
| 📊 导出   | 一键导出平时分 CSV（Excel 直接打开）  |

> 上面所有分值（加入 +1、前排 +3、答对 +2、抢答 +5/+3/+1、被点名 +2、
> 给前排加分 +2）都能在 `设置` 里改，改完三端文案同步跟着变。

## 四、服务器部署

**用 1Panel 部署请直接看指南**：

| 指南 | 适用 | 访问方式 |
| --- | --- | --- |
| [`部署指南-1Panel-Docker.md`](部署指南-1Panel-Docker.md) | **纯 Docker + 外部 WAF**：先构建镜像再建编排（推荐） | `https://你的域名` |
| [`部署指南-1Panel.md`](部署指南-1Panel.md) | 用 1Panel 自带 OpenResty 做反代并申请证书 | `https://你的域名` |

两份都按 1Panel 的界面逐步写，都处理了卷权限这个必踩的坑。
第一份更简单，也更贴合「容器只跑服务、外层另有 WAF」这种架构。

> ⚠️ **1Panel 创建编排时会自己预拉取 `image:` 声明的镜像**（源码
> `agent/utils/compose/compose.go`），`pull_policy` 对它无效。
> 所以 1Panel 的正确顺序是：**先构建镜像**（容器 → 镜像 → 构建镜像，或
> `docker build -t classroom-interactive:1.0.0 /opt/classroom-interactive`），
> **再创建编排**，编排粘贴 `deploy/docker/docker-compose.run.yml`
> （无 build 段），创建时**不要勾「强制拉取镜像」**。
> `docker-compose.yml`（含 `pull_policy: build`）只给命令行部署用。

通用 Docker Compose 部署看下面（非 1Panel 环境）。

### 1. 上传代码

把整个目录传到服务器，例如 `/opt/classroom-interactive`。
也可以直接用打包好的 `deploy/classroom-interactive-deploy.zip`（已排除
`node_modules`／`test`／`shots`）。

### 2. 配置域名（可选但推荐）

```bash
cp .env.example .env
vi .env
```

```env
# 学生扫码后访问的域名。填了它，二维码就固定用这个域名；
# 不填也能用，系统会按访问 Host 自动推断。
PUBLIC_BASE=https://class.yourdomain.com

# 生产环境建议设为 1，关闭房间列表接口
DISABLE_ROOM_LIST=1
```

### 3. 启动

```bash
docker compose up -d --build
docker compose logs -f app      # 看日志
curl http://localhost:3000/healthz   # 健康检查
```

**先看健康检查里的 `persistent` 字段**：

```json
{"ok":true,"rooms":0,"uptime":12.9,"persistent":true,"publicBase":"https://class.yourdomain.com"}
```

`persistent` 必须是 `true`。它是 `false` 说明数据目录不可写，数据只在内存里，
**重启就丢**。最常见的成因是卷权限：容器以 `node`（uid 1000）运行，而 bind mount
挂进去的宿主目录是 root 建的、权限 755，建子目录直接 EACCES。

解决办法二选一：改用 Docker 命名卷（会自动继承镜像内目录的属主，推荐），
或在宿主机执行 `chown -R 1000:1000 ./data` 后重启。

> 代码不会因此崩溃——目录不可写时会降级成「纯内存模式」继续运行，
> 课照样能上，同时在启动日志和 `/healthz` 里明确告警，不会静默丢数据。

数据落在命名卷 `classroom-data` 的 `/app/data/rooms/*.json`，重启、重建容器都不丢
（`persistent: true` 时）。备份：

```bash
docker run --rm -v classroom-data:/data -v /opt/backup:/backup \
  alpine tar czf /backup/classroom-$(date +%F).tar.gz -C /data .
```

### 4. 反向代理

容器里**不带** nginx，反代一律交给外部（WAF / 1Panel OpenResty / 已有 nginx /
宝塔），回源填 `http://127.0.0.1:3000`（同机）或 `http://服务器IP:3000`（异机）。

关键是 WebSocket 升级头，漏了它 Socket.IO 会退化成长轮询，弹幕和抢答会明显发飘：

```nginx
location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_read_timeout 3600s;
    proxy_buffering off;
}
```

**宝塔用户**：网站 → 反向代理 → 添加反代，目标 URL `http://127.0.0.1:3000`，
然后在配置文件末尾手动补上上面两行 `Upgrade` / `Connection`，否则实时推送会退化成轮询。

**WAF / CDN 用户**（如 swamwaf）：在控制台打开「WebSocket 支持」或「协议升级」开关。
验证方式：

```bash
curl -i -N -H "Connection: Upgrade" -H "Upgrade: websocket" \
     -H "Sec-WebSocket-Version: 13" -H "Sec-WebSocket-Key: SGVsbG8sIHdvcmxkIQ==" \
     "https://你的域名/socket.io/?EIO=4&transport=websocket"
# 期望 HTTP/1.1 101 Switching Protocols
```

### 5. HTTPS

必须在 HTTPS 下才能正常使用（iOS Safari 的麦克风/震动等 API 及部分浏览器策略要求）。
证书配在反代那一层，容器里不装证书。

### 6. 部署后自检

```bash
cd /opt/classroom-interactive
bash scripts/selfcheck.sh              # 检查本机 3000 端口
BASE=https://你的域名 bash scripts/selfcheck.sh   # 连公网入口一起验
```

依次检查容器状态、`/healthz`（持久化与二维码地址）、**服务实际吐出来的 JS
里有没有新功能的代码**、磁盘上的服务端文件、WebSocket 能否升级成 101。
哪一项不对就打印对应修法，失败时退出码非 0。

> 这一步专治「以为部署成功、实际跑的是旧包」：新功能早就在代码里，
> 但没重新打包或没重启容器，页面上什么新按钮都没有，而界面上没有任何地方
> 会提示"你用的是旧版本"。所以脚本不问版本号，而是直接问跑着的服务：
> **你有没有这个功能？**

## 五、上课使用流程

### 课前

1. 打开 `/c` → 填课堂名、座位表 → **创建课堂**
2. 点 **📺 打开大屏** → 把窗口拖到投影 → `F11` 全屏
3. 大屏上会显示大号二维码和 6 位课堂码
4. **📚 互动题库里把这次课要问的题先录好**（课上不用现场手打）

### 课中

1. 学生扫码 → 填昵称 → 选座位（大屏会冒出头像气泡；坐错了点自己的座位可重选）
2. 左侧选功能发布活动，大屏自动切换呈现；**也可以直接从题库点「📤 发布」**：
   - 讲概念 → 发投票，看有多少人真懂了
   - 讨论环节 → 开词云，观点自动聚合放大
   - 要提问 → 开转盘（用「仅前排」鼓励学生往前坐）
   - 抢答 → 前三名自动计分
3. **要讲结果就点「⏸ 暂停」**：停止收答案但结果留在大屏上，讲完再「▶ 继续」，
   都不用就「⏹ 结束」
4. 课间随时点「导出积分」留档

### 课后

1. 控制端 → **导出积分 CSV**，即平时分
2. 下次上课：控制端「回到上次的课堂」→ `设置 → 课堂管理 → 开始新的一课`
   （清掉上节的活动、座位与本次课得分，**名单和累计积分会自动留着**，同学打开手机会
   收到引导去重选座，**不用重新扫码填昵称**）
3. 房间数据保留在 `data/rooms/`，换班或新学期才用「清空全部数据」

### 教师鉴权（公网部署防被蹭课堂）

控制端有 **两套凭证**，任一匹配即可接管：

- **教师令牌**（`teacherToken`）：12 位随机字符串，建课堂时自动生成，
  控制端存在 localStorage，下次打开自动登录。
  浏览器清缓存或换设备 → 这个就失效了。
- **教师口令**（`teacherPass`）：6 位数字，**跨设备也能用**。
  建课堂时随机生成（写在这里或建课堂的二维码下方），
  也可 `设置 → 教师口令` 改成一个自己记得住的数。
  这是公网部署下"防别人直接扫码开课堂"的关键凭证。

连输错 3 次口令进入冷却（5×2ⁿ秒，封顶 5 分钟），冷却期内连正确口令也被拒；
冷却结束后自动放行。课堂码 + 教师口令都保留在 `data/rooms/<CODE>.json`，
跨设备打开同一课堂码即可登录。

## 七、常见问题

**Q：学生扫码打不开？**  
确认 `PUBLIC_BASE` 填的是能通过公网访问的域名，且服务器防火墙放行了 80/443。

**Q：大屏数据不实时？**  
99% 是 nginx 少配了 WebSocket 升级头。浏览器 F12 → Network → WS，看有没有 101 状态码。

**Q：投票结果和学生数对不上？**  
大屏显示的是「已作答 / 在线人数」，不是「已作答 / 总人数」。

**Q：学生换了手机/清了缓存，积分还在吗？**  
还在。积分存在服务端，浏览器只留一个 `studentId`。正常情况下凭它自动认领原身份；  
`studentId` 也丢了也没关系，会**按昵称认领**回原来那条记录，积分和座位都保留。  
认领只针对**当前离线**的同名记录——如果同名那位还在线，说明是另一位同学起了同样的  
名字，系统会给他另建身份，不会让两个人抢同一份积分。

**Q：服务挂了怎么办？重启后课堂还在吗？**  
在。房间状态每 2 秒防抖落盘到 `data/rooms/<课堂码>.json`。重启后教师用**原来的  
课堂码**进入（控制端会提供「回到上次的课堂」入口），名单、积分、座位、分组全部原样  
恢复；学生刷新一下页面即可自动重连。唯一丢的是「在线状态」和进行中的活动（投票进行  
到一半的票不算）。Docker 部署请把 `data/` 挂成卷，否则重建容器会清空。

**Q：支持多少人同时在线？**  
实测过，不是估的（`npm run load 200` 可复现，数字取自本机压测）：

| 规模   | 全员扫码进场 | 单次加入 p95 | 全员投票耗时 |
| ---- | ------ | -------- | ------ |
| 200  | 1.5s   | 9ms      | 0.1s   |
| 500  | 3.9s   | 13ms     | 0.3s   |

也就是说，常规课堂（几十到 200 人）毫无压力，500 人也依然是毫秒级响应。真正的瓶颈不
在服务端，而在**教室 WiFi 的带机量**——几十台手机挤在一个 AP 上，比这台服务器容易先
趴下。真遇到超大课堂，优先做的是换企业级 AP，而不是加服务器配置。

**Q：房间数据会一直攒着吗？会。**  
房间永不自动删除——这是有意的，老师可能想回到上周的课堂重新导出积分。所以：

- 磁盘：一节课一个小 JSON，一学期几百个文件、几 MB，可以不管。
- 内存：同样一直留着，只在重启时释放。单台服务器带一个老师用完一学期，可忽略。
- 界面：**不受影响**。控制端「回到上次的课堂」读的是浏览器本地记录，
  不列服务端全量房间，所以攒多少都不会变成一长串列表。

想清空某一节课：删掉 `data/rooms/XXXXXX.json` 后重启容器。

## 八、积分规则

| 行为              | 分值              |
| --------------- | --------------- |
| 扫码加入课堂          | +1              |
| **选择前排就坐**      | **+3**          |
| 参与投票            | +1              |
| 答对（设了正确答案时）     | +2              |
| 提交词语 / 弹幕       | +1（每人每活动上限 5 条） |
| 抢答第 1 / 2 / 3 名 | +5 / +3 / +1    |
| 被转盘点名           | +2              |
| 教师手动调整          | 自定义             |

规则集中在 `server/state.js` 的 `SCORE_RULES`，可按需修改——那是**默认值**。

上课时不用改代码：**控制端 `设置` 里可以直接调**，包括「加入课堂」
「前排就坐」「参与投票」「答对」「抢答第 1/2/3 名」「被点名」
「给前排同学加分」。改完立即生效，三端显示的「+N 分」文案会跟着变。
分值存在房间的 `settings.scoreRules` 里，重启后仍然有效。

## 十、开发自检

改完代码建议跑一遍。十组各自盯一段，全绿合计 **576 项**：

```bash
npm test          # 服务端逻辑与事件总线（52 项）—— 无需其他准备
npm run smoke     # 四个页面能否正常加载与加入（29 项）—— 自建课堂
npm run restart   # 服务被强杀后课堂数据还在不在（30 项）—— 独立端口
npm run mobile    # 手机端在 3 种真机尺寸下的排版（148 项）—— 无需其他准备
npm run wordblock # 词条屏蔽：撤下、拒收、跨重启保留、大屏实时消失（46 项）
npm run load      # 并发容量（11 项，默认 200 人；可加人数参数）
npm run loginlock # 教师口令连续输错后的冷却是否生效（8 项）
npm run legacy    # 旧版本课堂快照升级后能否正常读回（39 项）—— 独立端口
npm run demo      # 另开一个终端：造 14 位虚拟同学，配合下面两项
npm run verify    # 大屏视觉验证（76 项 DOM 几何断言）
npm run control   # 教师控制端点击是否真的生效（137 项）
```

| 检查                  | 抓什么                            | 抓不到什么   |
| ------------------- | ------------------------------ | ------- |
| `npm test`          | 房间状态机、积分、导出、事件是否送达           | 页面会不会白屏 |
| `npm run smoke`     | 整页脚本崩溃、新同学能否加入、关键元素在不在       | 排版是否错位  |
| `npm run restart`   | 进程被 SIGKILL 后积分/座位/分组是否还在     | 视觉与交互   |
| `npm run mobile`    | 小屏横向溢出、元素被切、点按区域过小            | 业务逻辑    |
| `npm run wordblock` | 屏蔽后是否真撤下、重复提交能否绕过、大屏是否同步消失   | 几何排版    |
| `npm run load`      | 多人同时进场/投票的耗时与票数是否丢            | 视觉与几何   |
| `npm run loginlock` | 口令被暴力猜时的冷却与解锁                | 业务逻辑    |
| `npm run legacy`    | 旧快照缺新字段时会不会读崩、降级是否正确         | 视觉与交互   |
| `npm run verify`    | 词云压字、柱状图比例、元素溢出、动画是否挂上        | 业务逻辑    |
| `npm run control`   | 教师点了按钮到底有没有生效、服务端拒绝时有没有提示    | 几何排版    |

`legacy` 是上线后加的：课堂一旦开过，`data/rooms/*.json` 里存的就是**当时版本**
写下的快照。升级代码后服务重启要把它读回来，新增字段（`sessionNo`、`questionBank`
、 `settings.scoreRules`）只要有一处没兜底就是启动即崩——而那一刻教室里可能正
坐着几十个学生。它用 `DATA_DIR` 环境变量指向临时目录 + 独立端口跑，不碰真实数据。

`restart` 容易被漏掉，但线上课堂最怕的就是它管的那件事：服务突然挂了，  
一节课的积分全没了。它用 **SIGKILL 强杀**（不给进程任何收尾机会）再重启，  
逐人比对积分、座位、前排标记是否原样恢复，并验证老同学凭本地 `studentId`  
重连后身份和积分都还在。

`mobile` 用 puppeteer 在 360×640 / 390×844 / 430×932 三种真机尺寸下量几何：  
有没有横向溢出、元素有没有被挤出屏幕、点按区域够不够手指点（<40px 就算不合格）。  
它抓到过真问题——座位图写死 40px 见方，8 列加间距共 369px，在 360px 的屏幕上  
首尾两列被切掉，改成按列数等分自适应才修好。

历史上正是靠 `smoke` 抓到"给只读的 `clientWidth` 赋值导致整页脚本崩溃"、  
靠 `verify` 抓到"侧栏列宽写成 0 导致积分榜被挤出屏幕"、  
靠 `test` 的新增用例守住"定向广播频道名不一致导致事件静默丢失"、  
靠 `control` 抓到"服务端拒绝时前端照样弹成功提示""设置里的弹幕/抢答开关存了但没被执行""服务端前排口径与前端不一致"、  
靠 `restart` 抓到"CSV 导出字段带引号导致积分断言在拿 null 和 null 比，恒真却什么都没测到"。

> `smoke`、`control`、`mobile`、`load` 都自建课堂、自带虚拟学生，**不依赖 `demo` 正在运行**；  
> 只有 `verify` 需要 `demo` 配合推进大屏状态。

### 写新测试时请带走的两条教训

压测脚本第一版在后台静默跑了 21 分钟才被发现，原因是两个低级疏漏：

1. **每个 `await` 都要有硬超时。** `socket.io-client` 在连接既不成功也不报错时会永远
   悬着，外层的 `await` 再也不会返回；ack 同理，事件名写错时服务端根本不回包。
2. **循环里要打进度。** 没有进度输出时，"跑得慢"和"已经死了"看起来一模一样。

另外，断言读不到数据时要先怀疑断言自己：`/api/room/:code` 只返回 `online/total`，
不含活动数据，想核对票数得从大屏连接的 ack 里取完整状态。

`npm run verify` 校验的是**几何事实**而非截图，例如：

- 词云任意两个词不重叠、不越出容器，且字号随频次递增
- 柱状图高度与票数严格成正比，不溢出轨道
- 座位图 48 个座位不溢出容器，前排带 ★ 标记
- 弹幕已挂上飞入动画、时长合理、在弹幕层内
- 转盘 Canvas 真的绘制了像素，扇区有多种颜色
- 页面无滚动溢出，舞台保持 1920×1080 定尺

想直接看效果，用 `node test/shoot.mjs`（需先跑 `npm run demo`），  
结果在 `shots/大屏-<状态>.png`，可直接插进 PPT。
